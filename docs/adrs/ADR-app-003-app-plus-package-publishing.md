## 功能开发说明

1. **发布线分离**：`app_apk_version` 管理 APK 版本，`app_release` 管理 WGT 资源版本；两类版本编码独立递增。
2. **APK 检查与摘要**：APK 检查比较原生版本编码；历史 APK 首次被检查时补算并保存 SHA-256，后续直接复用。
3. **WGT 清单解析**：从 WGT 内 `manifest.json` 读取资源版本名称和编码，用户只需填写更新说明及可选兼容要求。
4. **最低 APK 适配**：`minSupportedVersionCode` 表示最低兼容 APK；为空时不限制，满足 `当前APK版本 >= 最低APK版本` 才下发。
5. **独立检查接口**：`checkApk` 只返回 APK，`checkWgt` 只返回 WGT；WGT 不兼容时返回无更新，不回退完整包。
6. **维护页面**：WGT 上传页展示目标资源版本和最低兼容 APK；发布包只展示文件、大小及摘要。
7. **客户端顺序**：先提示 APK；非强制 APK 被跳过后继续检查兼容 WGT；APK 安装成功后等待重启，WGT 安装成功后主动重启。

## 决策

- APK 和 WGT 是同一应用下的两条发布线，不要求 WGT 精确绑定某个 APK。
- WGT 的兼容要求属于发布记录，不属于文件包；旧 `baseVersionCode` 停止参与新增和匹配，保留字段仅用于历史兼容。
- 原生代码、权限、插件或启动配置发生变化时发布 APK；仅资源变化时发布 WGT。
- 旧 `/release/check` 暂时保留并按 WGT 检查处理，新客户端使用 `/release/checkApk` 和 `/release/checkWgt`。

## 客户端流程

1. 读取当前原生 APK 版本并调用 APK 检查。
2. 有 APK 更新时优先提示；安装成功后本次不再处理 WGT。
3. 非强制 APK 被跳过或没有 APK 更新时，读取当前 WGT 资源版本。
4. 服务端筛选资源版本更高且满足最低 APK 要求的 WGT。
5. 下载并校验 SHA-256，安装 WGT 后重启应用。

## 验收标准

- WGT 上传时最低兼容 APK 可以留空，且不再校验 APK 与 WGT 版本编码的大小关系。
- 当前 APK 低于 WGT 最低要求时不下发；达到或高于要求时可以下发。
- APK 和 WGT 同时存在更新时先提示 APK；跳过非强制 APK 后仍可更新兼容 WGT。
- APK 安装成功后本次不继续安装 WGT；重新启动后根据新的 APK 和资源版本再次检查。
- WGT 不兼容或不存在时不会回退到 APK，APK 更新由独立检查接口决定。
- 新旧 APK 记录均可返回可校验的 SHA-256；草稿和撤回的 WGT 不下发。
